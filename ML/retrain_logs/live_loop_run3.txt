GraphSentinel -- the live loop, third run: the flood sent as many conversations
==============================================================================

Same route, machine, topology, daemon and services as ML/retrain_logs/live_loop_run.txt.
ONE variable changed in the traffic: the flood. Runs 1 and 2 sent it as a single
conversation (fixed source port); this run sends 500 SYNs from each of two hosts
with a new source port per packet, so the controller installs one table entry each.
Diff of the traffic scripts: ML/retrain_logs/live_loop/traffic.sh against traffic_manyflow.sh.

Three things differ in how the run was evidenced, all from code changed after run 2:
  * the backend was started with NO --log-config; its graphsentinel.* INFO lines
    print by default now (backend/app/logging_setup.py);
  * the provenance gate logs admissions (first, then once a minute);
  * the raw input is the daemon's own responses (DAEMON_DUMP_LOG), byte for byte
    what flow_parser was given, in ML/retrain_logs/live_loop/daemon_responses_run3.txt.
    Parsed again with flow_parser._parse_output they give 23526 flows, every one
    tagged 'ovs'; the gate reports 23526 flows admitted.
