# GraphSentinel — Integration Audit, 2026-10-04

A read-only audit of the frontend, backend, v1 model, chain bridge and
enforcement path, made by reading the code on `feat/integrate-graphsentinel-v2`.
It found 36 defects, B01–B36. Part 1 is what has happened since; Parts 2–4 are the
audit as it was reported, unchanged.

The audit covers the **v1 path** — the in-process model that creates incidents,
blocks hosts and writes to the chain (`MODEL_BEHAVIOUR.md` §1.1). The v2 engine's
internals were not audited.

At the time of the report the count was **1 P0, 7 P1, 18 P2, 10 P3**. Since then

### 1.3 B07 — the effect that was unverified, measured

The live test passes on the old code too. Measured on this machine (Windows,
Python 3.10), 15 emits from a non-server thread per condition:

| | delivered | median | worst |
|---|---|---|---|
| old (`asyncio.run`), long-polling | 15 of 15 | 78 ms | 219 ms |
| old, websocket | 15 of 15 | 62 ms | 125 ms |
| new (server loop), long-polling | 15 of 15 | 0 ms | 16 ms |
| new, websocket | 15 of 15 | 0 ms | 0 ms |

**B07 is reclassified from P1 to P3: a correctness fix with no observed
user-visible effect.** The old code delayed pushes by well under a tenth of a
second on a five-second poll cycle and dropped nothing. *n = 15 per condition, one
client, idle machine, Windows host; not measured under load, with multiple
clients, or in the Linux container* — the conditions in which a foreign event loop
usually bites. With B07 moved and B08 raised (1.4), the standing classification of
the 36 findings is **2 P0, 5 P1, 18 P2, 11 P3**.

### 1.4 B08 — measured, and it causes wrong blocks

`ML/b08_ovs_constants_check.py`, output in `ML/b08_ovs_constants.json`. The
committed labelled sample (18,264 flows, 1,674 attack) scored twice with the
installed v1 weights and the backend's own feature builder: once with the
direction and SYN columns, once with `fwd_ratio`, `byte_asymmetry` and `syn_ratio`
forced to the constants an OVS flow dump produces.

| at the tracked 0.75 threshold | offline features | OVS constants |
|---|---|---|
| precision | 0.9487 | 0.7994 |
| recall | 0.1326 | 0.3094 |
| benign flows scored as attacks | 12 | 130 |
| sources over the threshold | 21 | 45 |
| of those, sources that sent no attack flow | 11 | 31 |

794 flows change side. At 0.40, the value in the development machine's untracked
`backend/.env`, sources over the threshold that sent no attack flow go from 41 to
68.

Whether that is lost information or only a shifted operating point decides the
remedy, and one threshold cannot say. Threshold-free: average precision per flow
goes from 0.6292 to 0.5737 and per source from 0.3394 to 0.2967, and on OVS input
**no threshold reaches** the flow precision of 0.9487 that the offline features
had at 0.75. Re-tuning the threshold does not repair it. The full table is in
`MODEL_BEHAVIOUR.md` §1.2, which owns these figures.

By the audit's own test — "if it causes wrong blocks, this is P0" — **B08 is P0.**
The v1 path should not be presented as a detector on OVS traffic.

Limits. The v1 training and test sets are not in the repository, so this is not
v1's test set: it is the v2 sample, a small slice that is 90.8% benign and may
overlap v1's training rows. Overlap can only flatter the model, so the offline
column is a ceiling for traffic like this sample: with every feature present v1
finds at most 13% of the attack flows at 0.75, and at least 11 of the 21 sources
it would block sent no attack flow.

**No clamp.** Setting the three features to their training means when the source
is OVS would feed the model values no flow produced and hide the defect from every
distribution check. Since re-tuning the threshold is ruled out by the measurement,
the honest remedies are to retrain on OVS-sourced features, to retrain a
four-feature model, or to document the limit and stop presenting v1 as a
detector. None has been chosen; that decision is the project owner's.

### 1.5 B09 — confirmed on the dev server, and fixed

The audit had checked the production bundle only. Served by the Vite dev server,
which is what the Compose stack runs, every module that reads `import.meta.env`
carried `"VITE_BACKEND_API_TOKEN": "change-me-for-demo"` — the backend's operator
API key. No source file reads that variable. It is removed from `.env.docker` and
from `frontend/.env`; after removal the served module no longer contains it.
`frontend/.env` is now untracked, with `frontend/.env.example` in its place.

**The value remains in every earlier commit.** It is a demo default, so rotation
is not urgent, but any deployment that kept `change-me-for-demo` should change it.

### 1.6 Three compound risks the per-bug table does not show

**B03 + B12.** Until fixed together, one transient inference error made every
subsequent block a heuristic decision recorded on an immutable chain as
`GNN_DETECTED`, with no signal anywhere. For a project whose contribution is
provenance this was the worst defect in the list.

**B02 + B05 + no de-duplication on-chain.** Duplicate incidents per minute, plus a
timeout that can write the same incident twice, into a store that by design cannot
be corrected. Immutability is the feature, and it is also why duplicates already
written can never be cleaned up. B02 is fixed; B05 is open; the contract still
accepts any number of incidents for the same evidence.

**B24 + the 0.40 threshold.** Severity bands hard-code 0.75 and 0.50 while the
block threshold is configurable, and the development machine's `backend/.env` sets
0.40. As configured there, the system blocks hosts at a score whose alert is
labelled `info` (`NAMING_MAP.md`). One defect across two files; open.

### 1.8 What the verification and the figures guard did not cover

**`verify_stack.py` verified v2 only.** All nine of its checks concern the audited

identically while running v1 at different settings — Compose at 0.75 and

**A fresh clone was run** (`RUN_GUIDE.md` §6). `docker compose up -d` failed: the
backend's health check allowed 75 seconds, the backend needed more, and the
frontend was never started. The window is now 180 seconds. Without `ML/weights.pt`
checks 1, 4, 8 and 9 fail and the rest pass.

**The figures guard listed eight figures from memory.** Of the 113 distinctive

restatement to be declared and to stay equal to the owner. It recognises four
shapes — four-decimal values, thousands-separated counts, decimal percentages and

## Part 2 — Final report, as delivered

### GraphSentinel integration audit — final report (report only)

No code was changed, per your answer. The pasted prompt cut off at "Then output this summary block:", so I don't have that block's format and have not invented one.

### 1. Executive findings

- **What works:**
  - All 20 REST calls and the three socket events match on path, method and field names.
  - The v1 model's feature contract matches training exactly.
  - The contract ABI matches `IncidentLogger.sol`.
  - OVS commands are built without a shell and validated on both sides.
- **What's broken:**
  - The `readonly` role can trigger autonomous blocking.
  - Already-blocked hosts generate fresh incidents and chain writes.
  - Heuristic blocks are recorded as model detections.
  - One bad source IP aborts a whole batch.
  - The pending-transaction reconciler can be starved.
- **What's risky:**
  - The monitor pushes socket events from a foreign event loop.
  - Live OVS flows are out of distribution for the model.
  - A slow chain write can be recorded twice.

### 2. Integration health

| Link | Score | Why |
|---|---|---|
| Frontend ↔ Backend | Needs Attention | Contracts match, but authorisation (B01), alert triage (B17–B19) and role handling (B20) are wrong. |
| Backend ↔ ML | Needs Attention | Feature contract verified; degraded-mode labelling (B03, B12) and live-data mismatch (B08, B25) are not right. |
| Backend ↔ Blockchain | Needs Attention | ABI verified; outbox bugs B05, B06, B14 are proven in code. No live chain was exercised. |
| Backend ↔ Network | Unverified | Command construction and reconciliation read correctly; no Mininet/OVS run was performed. |
| Backend ↔ WebSocket | Unverified | The cross-loop emit (B07) needs a live run to confirm delivery; tests mock the socket server. |
| WebSocket ↔ Frontend | Healthy | Event names and payloads match, listeners clean up, no stale closures. Reconnect gives up after 5 tries (B16). |

### 3. Critical bugs

All are **RECOMMENDED FUTURE CHANGE — NOT APPLIED**.

**P0**
- **B01 — `readonly` can trigger blocking.** You confirmed the role is strictly read-only.
  - Where: POST `/analyze`, PATCH `/incidents/{id}/status` and POST `/blockchain/store` accept any authenticated identity ([analyze.py:19](backend/app/api/v1/analyze.py#L19), [incidents.py:37](backend/app/api/v1/incidents.py#L37), [blockchain.py:15](backend/app/api/v1/blockchain.py#L15)).
  - Impact: `/analyze` accepts caller-supplied flows, so a readonly user can get any host in 10.0.0.0/24 blocked and written to the chain.
  - Fix: add a dependency that rejects `role == "readonly"` on those three routes.

**P1**
- **B02 — already-blocked hosts are re-processed.** Add a `BlockedIP` check before `_create_incident` ([threat_analyzer.py:86-142](backend/app/services/threat_analyzer.py#L86-L142)).
- **B03 — heuristic blocks stored as `GNN_DETECTED`.** Read `prediction.get("mode")` at [threat_analyzer.py:105](backend/app/services/threat_analyzer.py#L105), and fix the test that hand-builds `ml_mode`.
- **B04 — one out-of-range IP aborts the batch.** Catch `ValueError` per IP at [threat_analyzer.py:91](backend/app/services/threat_analyzer.py#L91) and skip that host.
- **B05 — timeout can double-write to the chain.** The 5s adapter timeout is shorter than the client's 15s receipt wait ([blockchain_adapter.py:105-111](backend/app/services/blockchain_adapter.py#L105-L111)). Needs a design choice on which timeout wins; higher regression risk.
- **B06 — reconciler starvation.** The filter excludes `"Manual-Unblock"` but unblock rows are written as `"Manual"` ([reconciliation.py:181-190](backend/app/services/reconciliation.py#L181-L190)). Filter on `blockchain_status` instead.
- **B07 — cross-loop socket emit.** [monitor.py:270](backend/app/mininet_monitor/monitor.py#L270) should schedule onto the server's loop. Effect unverified; needs a live socket test.
- **B08 — live flows out of distribution.** Three of seven features are constant on OVS data ([graph_builder.py:51-67](backend/app/services/graph_builder.py#L51-L67)). This is a data limitation, not a small patch.

### 6. Performance findings

- **Chain reads scale with history.** `/forensics` makes 2N+1 synchronous RPC calls and a new filter per request, and each client polls it every 10s ([web3_client.py:237-259](blockchain/web3_bridge/web3_client.py#L237-L259)).
- **Polling never backs off.** Nine REST endpoints are fetched every 10s even while the socket is connected ([useGraphData.js:69-73](frontend/src/hooks/useGraphData.js#L69-L73)).
- **Timeline runs 24 queries per request** (12 buckets × 2 counts) ([timeline_service.py:20-38](backend/app/services/timeline_service.py#L20-L38)).
- **Every analysis builds a new enforcement agent**, which logs a "SIMULATED" warning each time, so one log line per 5s poll in simulated mode ([analysis_pipeline.py:20](backend/app/services/analysis_pipeline.py#L20), [enforcement_agent.py:71-72](backend/app/services/enforcement_agent.py#L71-L72)).
- **The frontend ships as one 2.69 MB chunk** (752 kB gzipped), measured from the build.
- **Not a problem:** the model, the chain client and the DB engine are each created once.

### 7. Security findings

- **Authorisation:** B01 (P0). The client also ignores the role (B20).
- **Socket auth:** checked only at connect (B15).
- **Command injection:** none found. The daemon uses argument lists, an IP validator and a switch allow-list; there is no `shell=True` in the backend.
- **Secrets in source:**
  - Demo default tokens and passwords live in [config.py](backend/app/config.py), guarded only when `environment=production`.
  - `frontend/.env` is tracked.
  - Hex private keys appear only in test files.
  - Ganache runs `--deterministic`, so its keys are public by design.
- **CORS:** explicit origin list for REST and Socket.IO; no wildcard.
- **Model input poisoning:** `/analyze` trusts caller-supplied flows, so anyone allowed to call it can cause a block. This is how the Simulate button works; B01 is what makes it dangerous.
- **DoS:** the `/forensics` cost above; a malformed `Content-Length` gives a 500 (B28); the analyze rate limit keys on a proxy-shared address (B35).
- **Daemon:** token compared with `!=`, plain TCP, default `test-token` (B26).
